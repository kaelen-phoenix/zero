## What Changes

- Turno nocturno 1b: autonomía por línea, tope diario, prioridad del dueño, freno de investigación, informe y README
- Supuesto: This removes a human gate: with `build` or `auto`, agent-written proposals become jobs, and with `auto` they become merges. The cap, protected paths, the verify gate and the manifest check are enforced by zero; review must treat this as security-relevant.
- Supuesto: Interpretation: in `build` mode the job is parked before integrating (the work branch is kept) rather than delivered as an unmerged pull request. When the owner approves, the job integrates per the line's integrate/autoMerge. A line with `branch` integration therefore only pushes its branch after approval.
- Supuesto: Interpretation: research-born third-party proposals take the more restrictive of the line's autonomy and research.autonomy.
- Supuesto: Interpretation: owner-first scheduling applies only to autonomous night-shift jobs; proposals the owner approved count as owner work.
- Supuesto: Whether a proposal is third party is detected from scout's flag, the proposal's paths and a fixed list of manifests. Vendored third-party code that touches no manifest can slip through as not third party.
- Supuesto: Promotion happens only when scout stores a proposal. Proposals left pending because of the cap or because autonomy was `propose` are not promoted later if the configuration changes.
- Supuesto: approveProposal may become async; the CLI, MCP and test callers must be updated.
