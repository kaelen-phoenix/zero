## 3. Etapa 3: Uploads to stations and safe unzip

- [ ] 3.1 Add src/unzip.ts, a pure Node module with no new dependency. It reads the zip's end-of-central-directory and central directory, and supports methods 0 and 8 (zlib.inflateRawSync, with the output capped per entry). It refuses the whole archive before writing anything when it finds encrypted entries, zip64, symlink entries (unix mode S_IFLNK in the external attributes), absolute or drive or `..` paths (after normalising backslashes), more than MAX_ENTRIES (e.g. 10,000) entries, or more than MAX_UNZIPPED_BYTES (e.g. 1 GiB) declared or real uncompressed bytes. It writes only under dest, and refuses a dest that is or lies under a symbolic link. It returns `{ ok: true, files } | { ok: false, reason }`.
- [ ] 3.2 In src/packages.ts `ManifestStationSchema`, add `uploads: { maxMb (positive, ≤100, default 20), extensions (default ['.zip']) }` as optional strict. Refuse uploads without onDemand. Carry it on `PackageStation` (src/config.ts type).
- [ ] 3.3 In src/app.ts, add `uploadToStation(ctx, ref, { name, content: AsyncIterable<Uint8Array> | Buffer, request? })`. It checks the station exactly like `requestStationRun` (refusing before writing), then the extension. It streams to a temp file in `<packageDataDir>/uploads/<station>/` and aborts and removes the file past maxMb. It checks the zip signature `PK\x03\x04` for .zip, renames the file to `<ISO-safe timestamp>-<sanitized basename>` and records kv `stationUploadKey(pkg, station)` with `{ name, path, sizeBytes, at }` before calling `requestStationRun`; on refusal it removes the file and the key.
- [ ] 3.4 In src/line/packages.ts, `runOnDemand` reads and clears the upload key together with the request, and `stationContext` takes an optional `upload` that becomes `ctx.upload`. Add `ctx.unzip(zip, dest)`, with both paths resolved and required inside `dataDir` (later also the package's repositories). It wraps src/unzip.ts and never throws.
- [ ] 3.5 Panel: `packagesPage` in src/panel/html.ts shows, for stations with uploads, a `<form method=post action=/packages/upload enctype=multipart/form-data>` with station, file and pedido. In src/panel/server.ts, handle `/packages/upload` after `sameOrigin` and before `readForm`: refuse when Content-Length is above the limit, wrap `req` in a byte-counting stream that errors past the station's maxMb plus multipart overhead, parse it with the platform's `new Request(..., { body, duplex: 'half' }).formData()`, then call `uploadToStation` and redirect back to /packages with the message.
- [ ] 3.6 CLI: in src/cli.ts, `zero package upload <paquete>/<estación> <archivo> [--pedido texto]` calls `uploadToStation` and, like `package run`, `waitStationStart`.
- [ ] 3.7 Tests: a new test/unzip.test.ts (zips built in the test with zlib: normal, traversal, absolute, symlink mode, too many entries, size bomb, dest outside), test/package-on-demand.test.ts (upload stored and ctx.upload received, too large leaves nothing, wrong extension, pending refused, manifest uploads without onDemand refused), and test/panel-packages.test.ts (multipart upload ok, cross-site 403).
