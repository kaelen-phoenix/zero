# Distributed factory

The same factory on several machines of the person in charge, coordinated through a private GitHub repository.

- `src/machine.ts` and `src/coord/`: the distributed factory (`docs/adr/0007-fabrica-distribuida.md`), off unless the factory file has `distributed` (strict: `repository` `owner/name`, `heartbeatSeconds` at least 30, default 60, `leaseMinutes` at least 2 and three heartbeats, default 10, optional `machine`). `machineIdentity` keeps the machine's id in kv `machine:id` (name from `machine` or the host); `machineCapabilities` declares only `platform`, `box` and `engines`. `protocol.ts` (`CoordApi`, `CoordConflict`, `memoryCoord`) holds `claimJob` (create `claims/<job>`; a closing record, an unreadable claim or an expired holder is taken over only from the tip read, an expired holder returned as `takenFrom`), `stillHolds` (false for a closing record), `releaseJob` (a compare-and-swap of the claim to a closing record `{job, machine, name, at, released: true, status}`, never a delete, since GitHub deletes refs with no expected tip), `readClaimOf`, `probeCoord` (creates `probe/<id>`, checks that creating it again and moving it from a stale sha give `CoordConflict`, then deletes it), `heartbeat` (`machines/<id>`, public fields only) and `listMachines`; `github.ts` (`githubCoord`) maps it to refs `refs/heads/zero-coord/*` on empty-tree commits of the private coordination repository, 422 becoming `CoordConflict`, never Actions. `coordPass` (`pass.ts`, the daemon's `coordinate`, at most every `heartbeatSeconds`, the meter's `coord` pass, skipped during `githubHalt`, off in `once` runs unless `DaemonOptions.coord` is injected) probes the repository first, once per `distributed.repository` and a failed probe again at most once an hour (`PROBE_RETRY_MS`), keeping `{repository, at, ok, problem?}` in kv `coord:probe`, then beats and stores the list in kv `coord:machines`, which `factoryStatus` gives as `FactoryStatus.machines` only with `distributed`, shown as the `Máquinas:` block (`machineLine` in `src/format.ts`) of `formatStatus` and the panel summary. `joinFactory` in `app.ts` (`zero unirse <owner/repo>`, an injectable `CoordRepoCheck` and `JoinDeps`: coord, cloner, platform, signal) writes `distributed.repository` through `editConfig` only for a private repository it can read; without a repository, or with an invalid name, a public one or an unreadable one it explains how to create it (`coordRepoHelp`: `gh repo create <owner/repo> --private --add-readme`, since GitHub refuses the records in a repository with no commits) and zero itself creates nothing. Once joined, `joinLines` probes the repository when no passed probe is kept (`probeOnce`, a failed one at once), runs `linesPass` once and tells what was cloned, what this machine does not take and what failed; a problem there (a pause, no token, a failed probe) is only told, the machine stays joined and the daemon tries again. Records read back are validated strictly (ids `[A-Za-z0-9-]`, ISO times, names without control characters). `coordReady` is true only with `distributed` and a passed probe of its current repository; the runner will rely on the protocol only then. Only while `coordReady` (and in `once` runs only with an injected `DaemonOptions.coord`), the daemon's queued loop calls `claimJob` right before `runJob` and skips a job it did not get (it stays queued, never failed; a claim error or a GitHub pause also skips it), passes the runner a `holds` dep (`stillHolds`, an unreachable repository counting as still held) and releases with `releaseJob` when `runJob` returns a final status, or `queued` after a shutdown; an andon, a quota stop, a question or a lost job keep the claim as it is. The runner asks `holds` (`ensureHolds`) before the conflict agents, spec, every build attempt, each writing agent, verify, each review, the approvals and integrate; a false answer throws `Interrupted("lost")`, which ends the job through `finalizeJob` as stopped with `LOST_TO_ANOTHER` ("Lo retomó otra máquina de la fábrica."), without integrating. `endedElsewhere` (`src/line/finish.ts`: that reason, `TAKEN_BY_ANOTHER` and `endedOn(name)`) makes `report` in `src/intake/github.ts` (GitHub, Linear, Jira) say nothing and the issue comments pass skip the job. The shared queue (`src/coord/queue.ts`, `queuePass`, run by `coordPass` after the heartbeat only while `coordReady`) lists `claims/` once and ends, through `finalizeJob` with that status and `endedOn(name)` ("Lo terminó la máquina <nombre>."), every local queued job whose claim is another machine's closing record of `delivered`, `failed` or `stopped` (`finished`); imports every `queue/<job>` record that reads strictly (`readQueueRecord`: id `[A-Za-z0-9-]` matching its ref, kind, request up to 100 000 characters, priority, a plain `source` of a known kind, ISO `createdAt`, `needs {box, engines}`) whose line exists here, whose id is not a local job and whose claim is not finished, as a queued job with the same id and `createdAt` (`Store.createJob` takes both) and the local `limits.usdPerJob`; and publishes every local queued job not yet published or imported (kv `coord:job:<id>` `{origin: published|imported, needs}`) as `queue/<job>` `{id, line, kind, request (scrubLocal), priority, source?, createdAt, needs}`, `needs.box` being a job started in the box or `isolation: container` with the box ready, and `needs.engines` the first engine of every agent station (`primaryEngines`). A job with a source first creates `sources/<sourceKey>` (a hash of the origin, the same on every machine; a package's requests are keyed by their job) naming it (`claimSource`); when the ref names another job, the local one ends stopped with `TAKEN_BY_ANOTHER` ("Lo tomó otra máquina de la fábrica.") unpublished, and its intake state (`issue:`, `linear-issue:`, `jira:` keys) is repointed at that job. Before claiming, the daemon skips an imported job whose `needs` this machine cannot meet (`canTake`: the box ready when asked, every engine in its stations' chains) and an imported job whose line is gone here (never failed), and claims with `keepFinished`, so another machine's closing record of an ended job is not taken over: the local copy ends with that status and `endedOn(name)` instead. While `coordReady`, the daemon also gives the runner a `pushProgress` dep (`src/coord/progress.ts`): at three checkpoints (after the spec is saved, after each stage that passes verify and right before integrate, `checkpointPush` in the runner) it checks `stillHolds` (false: `lost`, no `git push`; an unreachable repository skips the push), publishes the work copy and pushes `refs/heads/<branch>` from the line's repository to its `origin` with `--force-with-lease=refs/heads/<branch>:<sha>`, the sha being the last one this machine pushed (kv `coord:pushed:<job>`; none means the branch must not exist there). A push refused by the lease means someone else moved the branch: `lost`, and the job ends as `LOST_TO_ANOTHER`; a line without `origin` or any other push failure only logs and goes on. After a push it stores the sha and writes `progress/<job>` (`progressRef`) `{job, machine, checkpoint, stagesDone, branch, base, sha, title, spec, attempt, at}` by compare-and-swap from the tip read (create when missing; a conflict is `lost`). A job cut short by a shutdown on purpose pushes what is committed the same way before `runJob` returns it to the queue, and the daemon releases its claim right after, both before the daemon lock is released. Right after a claim, the daemon calls `resumeProgress` (`src/coord/progress.ts`) whenever `progress/<job>` names another machine or the claim came with `takenFrom`: it reads progress strictly (`readProgress`: the job's id, a `COORD_ID` machine, checkpoint `none`, `spec` or `review`, `stagesDone` up to `MAX_STAGES`, branch and base of plain ref characters with no `..` or leading `-`, a 40-hex sha, a spec that passes `SpecSchema` and `specProblems`), removes the job's old work copy, fetches the branch from the line's `origin`, sets it at progress's sha (its base must resolve here) and puts the job at that checkpoint with its spec, title, stagesDone, branch, base and attempt, so the runner skips what was pushed; an invalid or missing progress or a branch that cannot be brought starts the job from scratch (checkpoint `none`, the local branch deleted). Either way kv `coord:pushed:<job>` becomes the branch's tip on the remote, the lease of this machine's next push. A machine that comes back after another took its job over finds `stillHolds` false at its next station and ends as `LOST_TO_ANOTHER`, with no push, integration or comment.
- `src/coord/lines.ts`: the lines of a distributed factory. `linesPass` runs as the daemon's own background pass (`shareLines`, at most every `heartbeatSeconds`, through `protocol()` so only while `coordReady` and in `once` runs only with an injected `DaemonOptions.coord`, the meter's `coord` pass, skipped during `githubHalt`), never inside `coordPass`, so a slow clone holds up neither the heartbeat nor jobs; a shutdown cuts it and it is awaited in the `finally`. It publishes each local line whose `remote` is github.com itself as `lines/<name>` (`lineRef`; `LineRecord`: name, repository `account/name`, baseBranch, setup, verify, verifyTimeoutMinutes, integrate, autoMerge, needs `{engines: primaryEngines, platforms}`, machine, at), except package lines, lines it cloned, lines whose commands carry a local path or something like a secret (`scrubLocal` or `COMMAND_PATH` would change them) and anything `readLineRecord` would not accept; only the machine that created a record updates it, by compare-and-swap and only when it changed. Then it clones the lines of the other machines whose name is not in the factory file into `ZERO_HOME/lines/<name>` (`FactoryHome.lines`), from `https://github.com/<account>/<name>.git` only, and adds them with `addSharedLine` (through `editConfig`); a line that exists is never changed. The clone goes to a temporary `.<name>-*` folder there, renamed once it is whole and has the base branch; a folder already cloned from that repository by a cut pass is used as it is, and any other folder is refused. `gitCloneLine` (injectable as `DaemonOptions.cloneLine`) is git on its own with a 30-minute limit, https only, no prompts and no credentials of zero's: the person's credential helper gives them. `unattendedWhy` keeps out lines for another platform (the line's optional `platforms`: win32, darwin, linux) or that need an engine no chain here has, checked again on every pass. kv `coord:line:<name>` (`LineState`: `cloned`, `unattended` or `failed`, with `why`) keeps what was done: a `cloned` line taken out of the file by hand does not come back until `zero unirse` runs again (`forgetTakenOut`), and one this machine published itself never does, and a `failed` one is tried again after an hour (`CLONE_RETRY_MS`). The daemon's pass and `zero unirse` may clone a line at the same time: the first clone to finish stays, and a line the other process already added counts as cloned. `linesAway` (the `unattended` and `failed` lines whose name is not in the file) is `FactoryStatus.linesAway`, only with `distributed`, shown by `formatStatus` and the panel summary (`lineAwayLine`). `readLineRecord` is strict (`GITHUB_REPOSITORY`, `LINE_NAME`, `REF_NAME`, commands with no control characters up to 2000 each, no credentials) and gives back only the known fields. The setup and verify commands of a cloned line run on this machine: whoever can write in the coordination repository can add lines, and nothing else of the configuration.
