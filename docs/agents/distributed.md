# Distributed factory

The same factory on several machines of the person in charge, coordinated through a private GitHub repository.

- `src/machine.ts` and `src/coord/`: the distributed factory (`docs/adr/0007-fabrica-distribuida.md`), off unless the factory file has `distributed` (strict: `repository` `owner/name`, `heartbeatSeconds` at least 30, default 60, `leaseMinutes` at least 2 and three heartbeats, default 10, optional `machine`). `machineIdentity` keeps the machine's id in kv `machine:id` (name from `machine` or the host); `machineCapabilities` declares only `platform`, `box` and `engines`. `protocol.ts` (`CoordApi`, `CoordConflict`, `memoryCoord`) holds `claimJob` (create `claims/<job>`, take over an expired holder only from the tip read), `stillHolds`, `releaseJob`, `heartbeat` (`machines/<id>`, public fields only) and `listMachines`; `github.ts` (`githubCoord`) maps it to refs `refs/heads/zero-coord/*` on empty-tree commits of the private coordination repository, 422 becoming `CoordConflict`, never Actions. `coordPass` (`pass.ts`, the daemon's `coordinate`, at most every `heartbeatSeconds`, the meter's `coord` pass, skipped during `githubHalt`, off in `once` runs unless `DaemonOptions.coord` is injected) beats and stores the list in kv `coord:machines`, which `factoryStatus` gives as `FactoryStatus.machines` only with `distributed`, shown as the `Máquinas:` block (`machineLine` in `src/format.ts`) of `formatStatus` and the panel summary. `joinFactory` in `app.ts` (`zero unirse <owner/repo>`, an injectable `CoordRepoCheck`) writes `distributed.repository` through `editConfig` only for a private repository it can read. `zero repo crear <nombre> --coordinacion` (`createProject` with `coordination`, see `docs/agents/core.md`) creates that repository private with a first commit (the coordination adapter needs one), after the owner's confirmation, and joins it through `joinFactory` without cloning it or adding a line; it refuses `--publico`. The daemon does not claim jobs through the protocol yet.
