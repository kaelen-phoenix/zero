# Distributed factory

The same factory on several machines of the person in charge, coordinated through a private GitHub repository.

- `src/machine.ts` and `src/coord/`: the distributed factory (`docs/adr/0007-fabrica-distribuida.md`), off unless the factory file has `distributed` (strict: `repository` `owner/name`, `heartbeatSeconds` at least 30, default 60, `leaseMinutes` at least 2 and three heartbeats, default 10, optional `machine`). `machineIdentity` keeps the machine's id in kv `machine:id` (name from `machine` or the host); `machineCapabilities` declares only `platform`, `box` and `engines`. `protocol.ts` (`CoordApi`, `CoordConflict`, `memoryCoord`) holds `claimJob` (create `claims/<job>`; a closing record, an unreadable claim or an expired holder is taken over only from the tip read, an expired holder returned as `takenFrom`), `stillHolds` (false for a closing record), `releaseJob` (a compare-and-swap of the claim to a closing record `{job, machine, name, at, released: true, status}`, never a delete, since GitHub deletes refs with no expected tip), `readClaimOf`, `probeCoord` (creates `probe/<id>`, checks that creating it again and moving it from a stale sha give `CoordConflict`, then deletes it), `heartbeat` (`machines/<id>`, public fields only) and `listMachines`; `github.ts` (`githubCoord`) maps it to refs `refs/heads/zero-coord/*` on empty-tree commits of the private coordination repository, 422 becoming `CoordConflict`, never Actions. `coordPass` (`pass.ts`, the daemon's `coordinate`, at most every `heartbeatSeconds`, the meter's `coord` pass, skipped during `githubHalt`, off in `once` runs unless `DaemonOptions.coord` is injected) probes the repository first, once per `distributed.repository` and a failed probe again at most once an hour (`PROBE_RETRY_MS`), keeping `{repository, at, ok, problem?}` in kv `coord:probe`, then beats and stores the list in kv `coord:machines`, which `factoryStatus` gives as `FactoryStatus.machines` only with `distributed`, shown as the `Máquinas:` block (`machineLine` in `src/format.ts`) of `formatStatus` and the panel summary. `joinFactory` in `app.ts` (`zero unirse <owner/repo>`, an injectable `CoordRepoCheck`) writes `distributed.repository` through `editConfig` only for a private repository it can read. Records read back are validated strictly (ids `[A-Za-z0-9-]`, ISO times, names without control characters). `coordReady` is true only with `distributed` and a passed probe of its current repository; the runner will rely on the protocol only then. Only while `coordReady` (and in `once` runs only with an injected `DaemonOptions.coord`), the daemon's queued loop calls `claimJob` right before `runJob` and skips a job it did not get (it stays queued, never failed; a claim error or a GitHub pause also skips it), passes the runner a `holds` dep (`stillHolds`, an unreachable repository counting as still held) and releases with `releaseJob` when `runJob` returns a final status, or `queued` after a shutdown; an andon, a quota stop, a question or a lost job keep the claim as it is. The runner asks `holds` (`ensureHolds`) before the conflict agents, spec, every build attempt, each writing agent, verify, each review, the approvals and integrate; a false answer throws `Interrupted("lost")`, which ends the job through `finalizeJob` as stopped with `LOST_TO_ANOTHER` ("Lo retomó otra máquina de la fábrica."), without integrating. `endedElsewhere` (`src/line/finish.ts`: that reason, `TAKEN_BY_ANOTHER` and `endedOn(name)`) makes `report` in `src/intake/github.ts` (GitHub, Linear, Jira) say nothing and the issue comments pass skip the job. The shared queue (`src/coord/queue.ts`, `queuePass`, run by `coordPass` after the heartbeat only while `coordReady`) lists `claims/` once and ends, through `finalizeJob` with that status and `endedOn(name)` ("Lo terminó la máquina <nombre>."), every local queued job whose claim is another machine's closing record of `delivered`, `failed` or `stopped` (`finished`); imports every `queue/<job>` record that reads strictly (`readQueueRecord`: id `[A-Za-z0-9-]` matching its ref, kind, request up to 100 000 characters, priority, a plain `source` of a known kind, ISO `createdAt`, `needs {box, engines}`) whose line exists here, whose id is not a local job and whose claim is not finished, as a queued job with the same id and `createdAt` (`Store.createJob` takes both) and the local `limits.usdPerJob`; and publishes every local queued job not yet published or imported (kv `coord:job:<id>` `{origin: published|imported, needs}`) as `queue/<job>` `{id, line, kind, request (scrubLocal), priority, source?, createdAt, needs}`, `needs.box` being a job started in the box or `isolation: container` with the box ready, and `needs.engines` the first engine of every agent station (`primaryEngines`). A job with a source first creates `sources/<sourceKey>` (a hash of the origin, the same on every machine; a package's requests are keyed by their job) naming it (`claimSource`); when the ref names another job, the local one ends stopped with `TAKEN_BY_ANOTHER` ("Lo tomó otra máquina de la fábrica.") unpublished, and its intake state (`issue:`, `linear-issue:`, `jira:` keys) is repointed at that job. Before claiming, the daemon skips an imported job whose `needs` this machine cannot meet (`canTake`: the box ready when asked, every engine in its stations' chains) and an imported job whose line is gone here (never failed), and claims with `keepFinished`, so another machine's closing record of an ended job is not taken over: the local copy ends with that status and `endedOn(name)` instead.
