# Daemon

The background loop, job priorities, the single-daemon lock, the chat's MCP server and the factory's share of the GitHub quota.

- `src/priority.ts` (pure): job priorities `baja`, `media`, `alta`, `urgente`, stored on the job (`priority` column; absent or legacy rows default through `defaultPriority`: `baja` for autonomous night-shift and package sources, else `media`). `effectivePriority` raises a queued job one level per full 24 hours (`PRIORITY_AGING_MS`) up to `alta`. The daemon orders queued jobs with `ownerFirst` (effective priority, then `createdAt`, stable), starts an effective `baja` only with nothing running and nothing higher queued, and runs at most one `urgente` at a time. `requestWork` refuses `urgente` with a `source` (only the owner) and unknown levels; `setPriority` in `app.ts` (`zero priority`) changes an unfinished job. Pausing running jobs for an urgent one is not implemented.
- `src/daemon.ts`: background loop; `runDaemon` takes the lock before touching any state and releases it last. Only a loop that ends because it was asked to (SHUTDOWN_KEY, a signal, a `once` run) deletes its heartbeat (kv `daemon`) and writes kv `daemon-stopped` (`StopRecord`: `at`, `reason`), cleared at the next start; an error leaves the heartbeat. `daemonStatus` in `app.ts` (behind `FactoryStatus.daemon.state`/`since`) reads `running`, `unresponsive`, `stopped` or `crashed` (a heartbeat left, its process gone or older than the machine's boot, the lock free), and `formatStatus` shows `apagada a propósito desde HH:MM` or `se cayó (último latido HH:MM)` with the jobs left running. `reviveDaemon(ctx, start?)` starts a crashed daemon only when a job is `running` or `queued`; the CLI calls it after every command but `start` and `shutdown` (a stderr notice), and the MCP server at start (`reviveOnStart`) and after every tool call while `autoStart` is on (`ZeroMcpOptions.start` injects the starter). `src/daemon-lock.ts`: the single-daemon guarantee, an operating system lock on `daemon.lock` in ZERO_HOME (`acquireDaemonLock`, an empty SQLite file held in `BEGIN EXCLUSIVE`, which dies with the process and is not inherited; `daemonLockHeld`, a read-only look). `ensureDaemon` launches nothing while it is held (nor within 30 s of another launch, kv `daemon-launch`, which the daemon clears when it starts), `shutdownFactory` in `app.ts` waits up to 60 s for its release (`zero shutdown` exits 1 with the pid otherwise), and `daemonProcesses` lists daemon processes on the machine for `zero status` only, since it starts a process. `src/mcp/server.ts`: chat tools. `src/install.ts`: client registration.
- Unjam on demand in `src/daemon.ts`: `startUnjamOnDemand` runs a pending request (see [Night shift](night-shift.md)) in its own background pass, which takes no job slot and never holds the loop. Never two diagnoses at once: the loop starts it only with neither the idle run nor the daytime unjam at work (before considering either), both wait while it runs, and inside the idle run it goes between two steps, awaited, so it overlaps none of them. Off in `once` runs unless `DaemonOptions.unjamOnDemand` is set; a shutdown cuts it short, and the start of the daemon closes a record left open (`closeInterruptedUnjam`).
- Research on demand in `src/daemon.ts`: `runResearchOnDemand` runs a pending express request (see [Night shift](night-shift.md)) in its own background pass, which takes no job slot and, having its own cap, overlaps the idle run and the unjam passes. One at a time, with its own `AbortController`: the loop aborts it with reason `andon` when the andon is on, even with a factory file that does not load, and a shutdown aborts it through `researchStop`. Off in `once` runs unless `DaemonOptions.researchOnDemand` is set, and such a run stays up until it ends. The start of the daemon closes a record left open (`closeInterruptedResearch`).
- `src/github-quota.ts`: the factory's share of the account's GitHub quota. `githubMeter` (one per daemon) gives each pass (`merges`, `reverts`, `issues`, `proposals`, `research`, `scout`, `resolved`) an Octokit whose `request` hook refuses with `GithubHalted` during a pause, sends `If-None-Match` on GETs with a saved ETag (in memory, 500 entries; a 304 returns a `structuredClone` of the saved response, because pagination modifies what it receives), and keeps kv `github:quota` (only `core` or an unnamed resource), `github:halt` and `github:usage` (counts per pass for the current UTC hour). Inside the hook, options must change on the object it receives: the inner hooks are bound to it. `githubHalt` is the pause in force: a limit response (`isRateLimit`, until the later of `x-ratelimit-reset` and `retry-after`, or 60 s) or the 20% reserve while the quota is valid. The daemon starts no issue, proposal, research, merge or revert pass during one, and `endRun` logs each run's requests. `githubStatus` feeds the `GitHub:` line of `formatStatus`, shown at 40% or less or during a pause. `IssueApi.permission` rethrows limits instead of answering `none`. `src/tracker.ts` and the CLI stay outside the meter on purpose, so a finished job can still open its pull request.
