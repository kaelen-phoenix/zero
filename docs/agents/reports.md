# Reports

The townhall, the monthly report and the billing of external services.

- `src/townhall/`: collective memory and the owner briefing.
- `src/report.ts`: the monthly report per line (no model, no store writes, no daemon pass). `monthlyReport` in `app.ts` picks the lines and the month's finished jobs for `zero informe`, the panel's `/report` and `/report/export`, and `zero_monthly_report`; `report.ts` builds it (`reportText` cleans every stored text, on top of `scrubLocal`) and renders Markdown and standalone HTML. `saveReport` in `app.ts` is the only writer of a report file, for `zero informe --html` and `/report/export`: it writes to `<ZERO_HOME>/reports` and refuses when that folder falls inside a line's repository or the current folder's.
- `src/billing/`: what a line's external services cost per month, for the monthly report. `lines[].services` in the factory file (strict: `github` `{account?, type, repository?}`, `vercel` `{project, team?}`, `supabase` `{project, organization?}`; identifiers only, tokens are the secrets `GITHUB_BILLING_TOKEN` (falling back to the factory's GitHub token), `VERCEL_TOKEN` and `SUPABASE_ACCESS_TOKEN`). `records.ts` holds `BILLING_SERVICES` (label, source, secrets per service), the kv keys (`billingKey` per line, service and month; `billingDayKey`, the local day of the last read) and `BillingRecord` (`status` `ok` or `sin-dato`, optional `costUsd`, figures, a `reason` chosen by code). `readers.ts` has one read-only `BillingReader` per service over an injected fetch (10 s per request), which never throws and never keeps a token or a raw answer. `billingPass` (`pass.ts`, the daemon's background pass on the intake interval, off in `once` runs unless `DaemonOptions.billing` is injected) reads each service at most once per local day (mark set before the call), for the current month and for the previous one until a record read after it closed exists. `buildLineReport` adds the "Servicios" section and the "Total del mes (fábrica + servicios)" row only for lines with services, from those records alone. A new service is an entry in `BILLING_SERVICES`, a key in `services` and a reader.
